# DealHunter デモ操作ガイド

## 起動とログイン

作業フォルダで `npm.cmd run demo` を実行し、http://127.0.0.1:3100/login を開きます。

営業・エンジニア・リーダーそれぞれのデモ入力ボタンを押し、その後「ログイン」を押します。エンジニア9名とリーダー2名は選択欄で切り替えられます。リーダーのパスワードは共通で `demo-leader` です。別アカウントで試す際はヘッダーからログアウトします。

## 営業とエンジニアをまたぐ通し操作

1. 営業（青木 美咲）でログインし、「面談依頼を作成」を開きます。案件名・概要を入力し、担当リーダーに「佐藤 健一」、面談者に「高橋 蓮」「山本 葵」をチェックします。「候補日時を提示する」で開始日時を複数入力し、保存前の確認でリーダー・面談者全員を確認して保存します。終了時刻は入力しません。面談者は1名でも登録できます。
2. 通知の送信内容を確認します。Larkへは送信されず、アプリ内の履歴に残ります。
3. ログアウトしてエンジニア（高橋 蓮）で入り、「面談依頼」から今作った依頼を開きます。参加できる候補を複数選んで営業へ直接回答します。山本 葵で入ると山本宛ての依頼だけが表示され、回答は高橋と独立しています。
4. 営業で入り直し、「対応待ち N件／未確認 X件」を確認します。回答された依頼を選ぶと「確認済み」になり、未確認数だけが減ります。回答済みの候補を1つ選び、面談URLを入力して日時を確定します。
5. エンジニアで入り直し、「予定」で確定した日時と面談URLを確認します。営業側の予定と同じレコードです。
6. 「所感・質問」から該当面談を選び、業務内容・作業工程・リモート頻度・感想を入力します。質問は1問ずつ追加して提出します。
7. 営業で入り直し、「対応待ち」に新しい未確認の「面談結果・初回入場を登録」が届くことを確認します。提出内容と「質問集」も確認します。質問は案件に紐づき、案件詳細の過去質問にも表示されます。
8. その対応待ちから結果と初回入場の登録へ進みます。合格の場合は初回入場日時・集合場所・当日の案内を入力して保存します。不合格の場合は入場予定を作成しません。登録が完了すると、該当する対応待ちは一覧から外れます。
9. エンジニアで入り直し、「予定」で初回入場の集合時刻・集合場所・案内を確認します。
10. 面談詳細に表示される合否を読んで「確認」を押すと、その面談がエンジニアの予定一覧から外れます。初回入場の予定は別に残ります。
11. 初回入場が完了したら、その入場詳細の「確認」を押します。予定一覧から「入場中」へ移動し、入場中の案件概要・集合案内・元の面談や所感を引き続き参照できます。複数の案件がある場合も、それぞれの入場を確認して一覧に追加できます。

「確認済み」は内容を閲覧した状態で、対応完了とは別です。閲覧しても対応待ち総数は減りません。確認状態は再読み込み後も残りますが、日時確定前にエンジニアが候補を再回答すると、同じ依頼でも再び未確認になります。所感提出後の結果登録は別の対応待ちとして届くため、以前の確認済み状態は引き継ぎません。

初回入場が決まった後も、入場詳細の「案件概要」「元の面談」から面談時の内容・日時・URLを確認できます。「元の面談を見る」で面談詳細へ、「提出した所感を見る」（営業では「所感・聞かれた質問を見る」）で提出済みの記録へ進めます。営業・エンジニアの両方で利用できます。

同じタブで再読み込みしても入力済みの業務データは残ります。別タブを使う場合は、タブに戻るか再読み込みすると最新データを取得します。

エンジニアの「確認」はボタンを押した時に保存されます。面談結果が未確定の間は押せません。予定を開くだけでは移動せず、保存に失敗した時も元の一覧に残ります。確認状態は再ログイン・再起動後も保持され、営業側の予定や記録は削除されません。

## 日時を決めずに空き日時を確認する

営業の「面談依頼を作成」で、日程の調整方法を「面談者に空き日時を確認する」に切り替えます。

- 日付・時刻とも未定の場合は、日付の指定を空のまま保存します。
- 日付だけ決まっている場合は、カレンダーで複数の日付を選択し、開始時刻を入力せずに保存します。月を移動して別の月の日付も選択できます。同じ日付をもう一度押すと解除でき、「すべて解除」で日時未指定に戻せます。

エンジニアは自分宛ての依頼を開き、「都合のよい日時を回答」で日付と開始時刻を入力します。「候補日時を追加」で複数回答でき、日付指定がある場合はその日付から選択します。日時は日本時間です。

営業は「対応待ち」から、エンジニアが提案した開始日時を1つ選び、面談URLを登録して確定します。確定前であればエンジニアは回答を変更でき、再回答は営業側で再び未確認になります。確定後は候補を変更できません。

開始時刻だけの面談には終了時刻を自動補完しません。従来登録した終了時刻付きのデータは保持されます。

## スキルシートの添付とダウンロード

営業の「面談依頼を作成」で、面談者の下に「参画者」「参画者(ひらがな)」を入力できます。面談者とは異なる方を自由に登録でき、面談者の選択を変えても参画者名は上書きされません。両方とも任意入力で、ふりがなを入力する場合はひらがなを使用します。

スキルシートの添付欄は案件共通の1つです。PDF・Excel（xls/xlsx）・Word（doc/docx）、5MB以下を選択でき、同じ案件で選択したすべての面談者が同じファイルをダウンロードします。保存前の確認で、面談者・参画者・共通ファイル名を確認してください。

作成済みの依頼は、営業の「対応待ち」内の「作成した面談依頼」から詳細を開き、共通ファイルを追加・差し替えできます。差し替えは同じ案件の全面談者へ反映されます。受講者は自分の依頼詳細、関連する面談・入場詳細から「スキルシートをダウンロード」を押せます。案件外の受講者やリーダーは取得できません。

旧形式の個人別ファイルは自動共有せず保持します。共通ファイルが未設定の間は、本人の旧ファイルだけを表示します。共通ファイルを登録すると、全員がその共通ファイルを参照します。

## リーダーの状況確認

佐藤 健一でログインすると、自分がリーダーに選択された案件を一覧で確認できます。1案件の中に面談者全員の進捗が並び、案件を開くと概要・候補回答・確定日時／URL・所感／質問・合否・初回入場・入場中の記録を閲覧できます。面談者本人が確認して予定から外れた後も、リーダーには履歴が残ります。

検索は案件名・面談者名、絞り込みは各面談者の状態で行います。スマートフォンは案件をタップして詳細を読み、「一覧へ戻る」で戻れます。鈴木 遥には佐藤の案件は表示されません。リーダーは連絡の中継や承認をせず、営業と面談者が直接操作します。既存案件にはリーダーを自動割当せず、新しい依頼作成時に明示して選択します。

## 空の状態から確認する

新しいDBはデモアカウントだけの状態から始まります。営業で面談依頼を作成するまでは一覧が空です。すでに登録した案件がある環境では、そのデータは保持されます。

作成時に選んだエンジニアで入り直すと、その人宛ての依頼を確認できます。以降は上記の通し操作で進められます。サンプル案件を起動時に追加する処理は外しているため、再起動後も登録した案件だけが表示されます。

デモを一度に通して確認できるよう、面談日が未来でも自分の面談に所感を登録できます。すべて架空データを使用してください。Lark通知と外部カレンダーは送信内容のプレビューまでです。
