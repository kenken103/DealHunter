# 主要機能の実装・検証状況

## 2026年11月28日　面談・入場・管理者の操作改善

| 対象 | できること |
| --- | --- |
| 営業 | 回答期限と手動リマインドを設定し、面談者本人の面談・事前打ち合わせの重複を確定前に確認する。初回入場の変更・延期・取消と参画終了は担当営業が記録する。 |
| エンジニア | 直近の予定と要回答の依頼を確認する。所感・質問は下書きから再開でき、提出後の訂正履歴も参照できる。入場案内の既読と入場完了を別々に報告する。 |
| リーダー | 取込済み案件も含めて担当案件の進捗を確認する。面談者の選定時に会社別のNG理由を確認し、該当者を選んだ場合は判断者・日時・理由を残す。 |
| 管理者 | 会社メールと役割を指定して招待する。パスワードの再設定、利用停止・再開、所属や案件の担当変更を行い、案件の引き継ぎ履歴を確認する。 |

PC幅1440pxとスマートフォン幅390pxで、営業・エンジニア・リーダー・管理者の各画面を確認した。実際の案件を複製した検証用DBと架空の案件を使用した。管理者の初回ログイン・招待手順は[起動ガイド](../README.md#新規登録と管理者ログイン)を参照。

## 2026年11月20日　営業間の共有と面談担当NG検索

- 営業は全案件の予定・面談者・所感・結果・会社情報を参照できます。営業の案件更新操作は担当営業が行います。新規依頼の類似案件でも、担当を問わず担当営業名・案件名・面談概要を確認できます。
- 「面談担当のOK・NG検索」は、会社から全登録エンジニアを、エンジニアから全登録企業を照合します。NGを上位会社とエンド企業に分け、全営業の登録を合算します。各営業が解除できるのは自分の登録分です。
- 架空データを使った営業画面で、部分一致からの候補選択、同姓同名の区別、NGの優先表示、他営業のNGが残る場合の解除後の表示、取得失敗時の再試行を確認しました。PC幅1366px・スマートフォン幅390pxで双方向に検索できました。

## 2026年11月18日　面談の日程調整と参加案内

| 操作する人 | 対応した業務 |
| --- | --- |
| 営業 | 複数人の候補を並べて比較し、全員の共通時刻で一括確定。全候補不可なら再依頼し、URL未着なら日時を先に確定して「対応待ち」から後日登録 |
| 営業 | 同じ面談回に事前打合せと本面談の日時・URLを別々に登録。日時変更・延期・中止とその理由を保存 |
| エンジニア | 全候補不可・別日時・時間帯・「○時以降」を回答。各予定から接続手順・会議ID・パスコード・緊急連絡先を参照し、最新版を確認 |
| 営業・エンジニア | 面談回ごとに先方評価と準備事項を記録。評価の本人共有を選べ、結果確認後の新着案内も本人に表示 |
| リーダー・管理者 | 担当範囲で面談者ごとの予定状態・本人の案内確認・変更履歴を参照。営業・管理者向けの非公開評価はリーダーにも非表示 |
| 営業 | 案件一覧と新規依頼で、取引先と面談者の組み合わせから別案件を含む提案・面談履歴を参照 |

PCと390px幅の実画面で、候補再依頼、共通時刻での2人一括確定、URLの後日登録、本人による案内確認、リーダー・管理者による履歴参照、取引先と面談者からの履歴検索を確認しました。Java・PostgreSQLの統合検証では、一括確定の競合時に一部だけが登録されないこと、非公開評価の編集が本人の既読を変えないこと、従来の日程回答、二次面談・初回入場までの業務フローも確認しました。

- 通常のLark通知と外部カレンダー登録は送信内容をプレビューします。日時未確定の依頼を削除したときの通知は、通知先を設定すると送信できます。

- スマートフォン確認はデスクトップブラウザの390px幅で、実機Lark内ブラウザは未確認です。

## 再確認コマンド

プロジェクトのルートから実行します。統合テストは専用案件を作るため、ブラウザでの登録・更新と同時には実行しないでください。

```powershell
npm.cmd run build
npm.cmd run verify:auth
powershell -NoProfile -ExecutionPolicy Bypass -File backend/verify.ps1
node backend/verify-attachment.mjs
node backend/verify-availability.mjs
node backend/verify-recruitment.mjs
node backend/verify-companies.mjs
node backend/verify-accounts.mjs --with-frontend
# アカウント情報を実再起動後に確認する場合
node backend/verify-accounts.mjs --with-frontend --prepare
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-backend.ps1 -Restart
node backend/verify-accounts.mjs --with-frontend --persisted
```

多段の保存保持テスト（leader-multi／task-ack）は、スクリプトが表示する再起動・persisted・continue・cleanupの手順に従います。
