# 営業向け「類似案件のお知らせ」

同じ案件が、担当営業や商流によって別の案件名・概要で登録されることがある。新しい面談依頼を作る営業が、配信前に既存案件との共通点を確認し、必要に応じて担当営業と相談できるようにする。

## 営業から見た流れ

1. 営業が通常どおり、案件名・上位会社・エンド企業・面談概要を入力する。営業が面談者を直接選ぶ場合も、リーダーへ選定を依頼する場合も対象。
2. 「依頼内容・Lark通知を確認」を押したときに照合する。入力途中には割り込まない。
3. 一致度75%以上の候補があれば、今開いているポップアップを「同じ案件の可能性があります」という表示に切り替える。上位3案件を一致度順に表示し、各候補に一致度と理由を添える。複数の面談者や選考回があっても1案件につき1件とする。
4. 「入力に戻る」で下書きを保ったまま編集できる。「このまま確認へ進む」は従来の保存前確認へ進む。この時点では依頼を保存しない。候補なしなら従来の確認へ直接進む。照合が失敗した場合は「類似案件を確認できませんでした」と表示し、「再試行」「確認へ進む」を選べる。

この通知は作成中の営業本人にのみ表示する。候補の既存案件と新規依頼は独立して扱い、統合・担当変更・Larkへの送信には個別の業務判断を必要とする。

### ポップアップの表示例（架空）

```text
同じ案件の可能性があります

一致度 82%　配送経路の最適化システム
担当営業　山田

エンド企業が一致　／　業務内容が類似　／　上位会社が異なる

［案件を確認］
［入力に戻る］　［このまま確認へ進む］
```

## 一致度の計算

| 比較する項目 | 配点 | 比較方法 |
| --- | ---: | --- |
| 面談概要 | 65 | 表記を整え、業務内容・対象システム・工程などの文章の類似度を0〜1で計算する |
| 案件名 | 15 | 表記を整えた文字列の類似度を0〜1で計算する |
| 上位会社 | 10 | 正規化した社名が同一なら満点。別会社なら0点 |
| エンド企業 | 10 | 上位会社と分け、エンド企業同士で比較する |

**一致度 = 四捨五入（各項目の獲得点の合計 ÷ 比較できた項目の配点合計 × 100）**。社名が片方でも未入力の項目は分母から外し、空欄同士の一致で加点しない。「82%」は登録情報から計算した類似の度合いを示す。実際に同一案件である確率を推定した値ではない。

例として、概要の類似度が0.92、案件名が0.80、上位会社は別、エンド企業は同一の場合、獲得点は 59.8＋12＋0＋10 で、表示は **82%**。上位会社が違っていても通知できる。一方、同じ上位会社から届いた別案件は会社名だけで通知しない。

- 全角・半角、英字大小、連続空白などを正規化し、「（株）」と「株式会社」のような法人格表記を揃える。支店名、製品名、バージョン番号などの違いは残す。
- 初版は外部AIに案件情報を送らず、サーバー内で日本語の連続2〜3文字を比較する。登録案件での出現頻度で重み付けし、挨拶文、募集テンプレート、頻出技術名だけの一致を弱める。
- 通知の条件は「総合75%以上、かつ概要の類似度0.55以上」。定型句を除いた概要が20文字未満の場合は判定材料不足として自動通知しない。文面を全面的に書き換えた同一案件は見逃す可能性がある。

## 比較対象と閲覧権限

営業は全案件を閲覧できる。照合の対象はすべての登録済み案件で、上位会社や面談者が異なる案件も候補になる。自分の担当・他の営業の担当とも、案件名、担当営業、一致度、一致理由を表示する。「案件を確認」を開くと、作成中の依頼を保ったまま登録済みの面談概要を読める。既存案件の更新はその案件の担当営業が行う。

## 実装と受入確認

- 新規作成フォームの保存前確認から、営業専用の読み取りAPI（`POST /api/similar-projects`）に案件名・面談概要・上位会社・エンド企業を渡す。Java側で案件単位に採点し、表示が許可された情報だけを返す。比較に面談者の個人情報やスキルシートは使わない。
- 同じ下書き・同じ比較項目で確認画面を往復しても通知を繰り返さない。比較項目を編集すれば再照合する。PC・スマートフォンともに既存ダイアログの中で遷移し、ダイアログを二重に開かない。
- 初期値は精度の実績ではない。営業が同一・別案件と判断済みの組み合わせを使い、誤通知と見逃しを確認して配点・閾値を調整する。
- 受入例は、①異なる上位会社で概要が近い案件、②同じ上位会社だが内容が違う案件、③募集テンプレートだけが同じ案件、④エンド企業が空欄の案件、⑤他担当案件でも案件名・担当営業・概要を参照できること、⑥照合失敗後の再試行と下書き保持。

JavaとPostgreSQLの照合テストは、プロジェクト直下から次のコマンドで実行する。専用のデータベースに架空案件を登録し、順位・誤通知・閲覧権限・照合前後の登録件数を確認する。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-end-companies.ps1 -SimilarProjects
```
