# DealHunter

SESの面談依頼から日程回答・所感・合否・初回入場までを確認できるローカルアプリです。会社メールによる新規登録、営業／エンジニア（受講者）／リーダーのホーム、管理者による役割・所属の編集に対応しています。Next.js＋TypeScript、Java、PostgreSQLで構成しています。

## 起動

必要環境：Git、Node.js 20.9以降（npmを含む）、JDK 21以降、PostgreSQL 17。付属の起動スクリプトはWindows PowerShell用です。初回は依存ライブラリを取得するため、インターネット接続が必要です。

初めて取得する場合は、PowerShellで次を実行します。取得済みならプロジェクトのフォルダで `npm.cmd run demo` だけを実行してください。

```powershell
git clone https://github.com/kenken103/DealHunter.git
cd DealHunter
npm.cmd run demo
```

初回は `npm ci`、Java依存ライブラリ（PostgreSQL JDBC・Jackson）の取得、専用DBの初期化を自動実行します。その後、Java API・PostgreSQL・Next.jsが起動します。ターミナルを開いたまま、次へアクセスしてください。

[ログイン画面を開く](http://127.0.0.1:3100/login)

ログイン画面の「デモで試す」で、利用する人を選択して「ログイン」を押してください。Excel取込後は、取込時に作成した人を選ぶと、その人用のメールアドレスと共通の仮パスワードが入力されます。

以下はExcelを取り込む前の初期デモアカウントです。

| --- | --- | --- | --- |
| 営業（青木 美咲） | sales.aoki@dealhunter.example | demo-sales | `/sales` 営業ホーム |

区分はサーバーに登録したアカウントで判定します。各画面の「ログアウト」でログイン画面へ戻れます。

### 新規登録と管理者ログイン

[新規アカウント登録](http://127.0.0.1:3100/register) で、氏名・メールアドレス・パスワードと、エンジニア／リーダー／営業の役割を登録できます。メールはドメインが `legarea.jp` と完全一致するものだけを受け付けます。`user@sub.legarea.jp`、`user@evillegarea.jp`、`user@legarea.jp.example` は登録できません。メールは前後の空白除去・小文字化後に重複を検証します。パスワードは10〜128文字で、DBには個別のソルト付きPBKDF2-HMAC-SHA256（600,000回）のハッシュを保存します。

初回起動時に管理者 `admin@legarea.jp` を作成します。初期パスワードは起動した環境の `.local/initial-admin-password.txt` を開いて確認し、通常のログイン画面に入力してください。パスワードは環境ごとに生成し、Gitには含めません。既存の管理者や認証情報を再起動時に初期化しません。

[管理者画面](http://127.0.0.1:3100/admin) では利用者を検索し、役割（エンジニア／リーダー／営業／管理者）と、エンジニアの所属リーダーを変更できます。一般の新規登録では管理者を選べません。役割変更後は次のアクセスから新しい権限とホームが適用され、過去の面談・所感・案件は保持します。部下が所属中、または面談者の選定待ちが残るリーダーは、所属変更・選定完了を先に行います。最後の管理者の役割変更は拒否します。

初期デモではエンジニア9名、リーダー2名を切り替えられます。エンジニアのデモパスワードは共通で `demo-engineer`、リーダーは `demo-leader` です。リーダーは担当案件の面談者選定と進捗閲覧ができ、営業の日時確定・結果登録や面談者本人の回答を代行できません。

初期デモの所属は次のとおりです。リーダーが選定できるのは、自分のチームの部下だけです。

| リーダー | 所属するエンジニア |
| --- | --- |
| 佐藤 健一（5名） | 高橋 蓮、山本 葵、森 彩乃、伊藤 航、小林 悠 |
| 鈴木 遥（4名） | 佐々木 凛、田中 陸、木村 楓、井上 葵 |

`JAVA_HOME` が設定されていなければPATH上のJavaを、`DEALHUNTER_POSTGRES_BIN` が未設定ならPATH上の `psql.exe` のフォルダを使います。自動検出できない場合は、インストール先に合わせて設定してから起動します。

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21'
$env:DEALHUNTER_POSTGRES_BIN = 'C:\Program Files\PostgreSQL\17\bin'
npm.cmd run demo
```

フロントエンドはCtrl+Cで終了します。Java APIと専用PostgreSQLも停止する場合：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-backend.ps1
```

停止しても登録データは残ります。別のPowerShellで停止する場合は、起動時と同じ `DEALHUNTER_POSTGRES_BIN` の設定を使ってください。

## 個別起動・再起動

依存関係を `npm.cmd ci` で取得後、次の順で実行できます。Javaソースはバックエンド起動時にコンパイルされるため、MavenやGradleの実行は不要です。

```powershell
# Java APIと専用PostgreSQLをバックグラウンド起動
npm.cmd run backend
# フロントエンドを起動（Ctrl+Cで終了）
npm.cmd run dev
```

Javaの変更を反映するときは、次を実行します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-backend.ps1 -Restart
```

本番ビルドをローカル確認する場合は `npm.cmd run backend`、`npm.cmd run build`、`npm.cmd start` の順に実行します。URLは開発時と同じです。

## 別PCに現在のデータを移す

元のPCのプロジェクトフォルダでバックアップを作成します。専用PostgreSQLが停止していれば自動で起動します。

```powershell
npm.cmd run db:backup
```

出力先は `.local/dealhunter-data.dump` です。利用者のパスワードハッシュ、案件、面談履歴、添付ファイルなどを含みます。アクセス権のある保管先で管理し、許可された方法で別PCへ移してください。`.local/` はGit管理対象外です。

別PCでは上記の必要環境を用意し、元のPCと同じコミットのソースを取得します。プロジェクト内に `.local/` を作り、バックアップを置きます。プロジェクトフォルダで、初回起動より先に復元コマンドを実行します。復元コマンドは初期化済みのDBを検出すると中止します。

```powershell
npm.cmd run db:restore -- -BackupPath '.\.local\dealhunter-data.dump'
npm.cmd run demo
```

[ログイン画面](http://127.0.0.1:3100/login)を開き、元のPCで使っていたアカウントのメールアドレスとパスワードでログインしてください。管理者の認証情報もバックアップ時点のものです。初期管理者パスワードのファイルが必要な場合は、元のPCで確認してください。

ログインセッションや内部キーはPCごとに作成されます。Larkカレンダー連携を使う場合は、別PCで `.local/lark-calendar.json` を設定してください。

## 構成

- Next.js App Router / TypeScript / React：ログイン、新規登録、営業・エンジニア・リーダーのホーム、管理者画面（`127.0.0.1:3100`）
- Java 21：JDK標準HTTPサーバーとJDBCによる業務API（`127.0.0.1:8080`）。Spring Bootは使用していません。
- PostgreSQL：案件・利用者・面談依頼・候補日時・回答・予定・所感・質問・通知プレビュー（`127.0.0.1:15432`）
- データ経路：ブラウザ → Next.jsの認証付きAPI → Java API → PostgreSQL

専用データベースは `.local/postgres` に作成します。既存PostgreSQLのデータや設定を変更しません。生成パスワードは `.local/database.password` に保存し、Git管理対象から除外しています。3つのサーバーはループバックでのみ待ち受けます。

## 今回の範囲

### Larkカレンダーから空いている面談者を探す

営業の「面談依頼を作成」→「日時から面談者を探す」で、日本時間の日付・開始・終了を指定します。検索時点でその時間全体が空いている人を、結果から面談者に追加できます。Larkに予定がある人、確認できない人、DealHunterの確定面談と重なる人は候補から外れます。検索と候補選択は予約を作成しません。

1. Lark管理者が社内用のカスタムアプリでBot機能を有効にし、カレンダーの空き時間の読み取り権限 `calendar:calendar.free_busy:read` を追加します。メールアドレスで本人を照合する場合は `contact:user.id:readonly` も追加します。対象社員をアプリの利用・連絡先のアクセス範囲に含め、権限を反映したバージョンを公開してください。[カレンダー照会仕様](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/calendar-v4/freebusy/batch.md)・[メールからのID照合仕様](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/contact-v3/user/batch_get_id.md)
2. [設定例](backend/lark-calendar.example.json)をプロジェクト直下の `.local/lark-calendar.json` にコピーし、`appId` と `appSecret` にこのアプリの値を入力します。設定ファイルはGit管理外で、Javaサーバーだけが読み込みます。
3. `npm.cmd run demo` を実行します。設定を変更したときも同じコマンドで反映できます。

標準ではDealHunterのログインメールをLark連絡先の登録メールと照合します。Larkの法人メール欄だけに登録されているアドレスやデモアカウントは自動照合できません。個別に紐付ける場合は、設定ファイルに以下のように `openIds` を追加してください。この方式では記載した人だけを対象にし、連絡先を照会しません。Open IDはこのアプリ用に発行された値を使います。[Open IDの確認方法](https://open.larksuite.com/document/uAjLw4CM/ugTN1YjL4UTN24CO1UjN/trouble-shooting/how-to-obtain-openid)

```json
{
  "appId": "アプリのApp ID",
  "appSecret": "アプリのApp Secret",
  "openIds": {
    "対象者のDealHunterログインメール": "ou_対象者のOpenID"
  }
}
```

読み取るのは主カレンダーの予定あり・なしの時間帯です。Larkに連携された外部カレンダーの予定も照会に含めます。予定名・参加者一覧の取得や予定の作成・変更は行いません。

予定表は日本時間の当日を基準に表示します。営業は他の営業が担当する案件も閲覧できます。日時・合否・初回入場などの更新は案件の担当営業が行います。新しいDBには利用者とチーム所属が登録され、案件関連データは空の状態から開始します。営業の「面談依頼を作成」から登録して試せます。

- 「すべて／面談／初回入場」、日付・週・月移動、今日へ、直近予定への移動
- `@legarea.jp` 限定の新規登録とパスワードログイン、管理者による役割・エンジニア所属の変更
- 選択した面談の日時・受講者・デモURL・案件別の過去質問
- 初回入場の集合時刻・集合場所・当日の案内
- 営業が初回入場を登録するとき、同じ受講者が別案件で同じ日（日本時間）に入場する予定があると警告します。日時を直すか、重複を確認して登録するかを選べます。重複する予定には、他の営業が担当する案件も含めて案件名と時刻を表示します。
- 対応待ち総数／未確認数の表示、閲覧による確認済みの保存、再回答時の再未確認、質問集から該当案件への移動
- 営業による面談依頼の作成とDB保存。面談者を直接指定するか、面談者未定で担当リーダーに選定を依頼
- 新規依頼で「依頼内容・Lark通知を確認」を押すと、登録済み案件と照合します。類似案件があれば、一致度と共通点を最大3件表示します。すべての候補で案件名と担当営業を表示し、「案件を確認」から面談概要を読めます。[判定方法と表示範囲](docs/similar-project-alert-design.md)
- 新規の面談依頼に「上位会社（必須）」「エンド企業（任意）」を登録。保存前の確認と保存後の案件詳細に表示し、面談・初回入場でも同じ案件の会社情報を参照
- リーダーは担当の選定依頼で、自チームの部下を1名以上選択。選定後に面談者別の依頼を作成し、既存の日程回答・日時確定へ進行
- 営業は日時を指定するか、日時未指定・日付指定で空きを照会。面談者は参加できる候補、全候補不可、代替日時を回答でき、「13時〜15時半」「18時以降」の時間帯も指定可能
- 営業の「対応待ち」から面談者ごとの回答を比較し、共通時刻で一括確定。URLが届く前に日時を確定でき、URLの追記も「対応待ち」から操作可能
- 面談者の決定後は営業と各面談者が直接回答・日時確定を進め、リーダーは担当案件の全員の状態・概要・所感・結果・入場記録を継続閲覧
- 事前打合せと本面談には別々の日時・URLを登録。会議ID、パスコード、当日の準備、緊急連絡先を本人の予定から参照。営業による日時変更・延期・中止は、理由とともに面談履歴に保存
- 面談者は最新版の参加案内を確認。共有内容を変更すると再確認が必要になり、営業と担当リーダーが確認状況を参照可能
- 面談回ごとに先方評価と次回の準備事項を記録。評価の本人共有を選択でき、所感提出・結果確認後も共有された内容を参照可能
- 営業の「案件一覧」で取引先（上位会社・元請け・エンド企業）と面談者を指定し、案件をまたいで提案・面談履歴を検索。新規依頼の作成中にも同じ組み合わせの履歴を確認可能
- 営業メニューの「OK・NG検索」から、会社名とエンジニア名の両方向で検索できます。上位会社・元請け・エンド企業のいずれかが過去の面談先と一致するとNGです。「面談担当NGを手動登録・解除」では履歴にない会社名も入力できます。手動登録は全営業で共有され、解除できるのは自分の登録分です。
- エンジニアによる業務内容・作業工程・リモート頻度・感想・質問の登録
- 所感提出後の営業向け対応待ち、面談結果・初回入場案内の登録
- エンジニアによる面談結果の確認と予定一覧からの非表示、初回入場の完了確認、複数の「入場中」案件と概要の参照
- 面談者と別に参画者・参画者のひらがなを保存・表示
- 案件共通のスキルシート1件の添付、作成済み依頼への追加・差し替え、対象面談者と全営業によるダウンロード（PDF／Excel／Word、5MB以下）
- 通知・カレンダー送信内容のローカルプレビュー
- スマートフォンでの詳細への移動と、選択した一覧行への復帰

ログイン済みアカウントに応じてホームと取得データが切り替わります。営業は全案件を閲覧でき、営業による案件の更新はその担当営業に限ります。エンジニアは自分宛ての依頼、自分の予定と所感を確認し、自分の回答を登録できます。リーダーは自分が設定された案件の全面談者を閲覧でき、未選定の依頼に対する自チームの面談者選定だけを更新できます。日程回答・日時確定・所感・合否・入場登録など、それ以外の業務更新は拒否されます。同じ案件の過去質問は共有しますが、別面談者の所感本文はエンジニアへ返しません。Next.jsのセッションは署名・期限付きのHttpOnly Cookieで保持し、署名鍵は `.local/demo-auth.key` に保存します。

新規登録とパスワードログインは実装しています。公開された架空のデモアカウントも引き続き利用できます。メールアドレスの所有確認・パスワード再発行・HTTPSでの外部公開は未対応です。ドメイン検証だけではメールの所有を確認できません。Java APIはNext.jsとの内部キー（`.local/api-key`）と利用者IDを検証し、DB上の区分と案件との関係を判定します。

業務入力はPostgreSQLに保存され、再読み込み・アカウント切り替え・再起動後も残ります。Lark通知の実送信と外部カレンダー登録は行わず、送信内容をローカル履歴として保存・表示します。初期面談URLは架空のデモ用URLです。

新しい面談依頼では「上位会社（必須）」と「エンド企業（任意）」をそれぞれプルダウンから選びます。全営業の登録済み社名が、上位会社・エンド企業の区分ごとに候補に表示されます。初めて使う社名は「新規追加」を選び、200文字以内で入力してください。案件を保存すると、次の依頼から選べます。管理者は「案件管理」で全案件のエンド企業候補を参照できます。

通し操作は [デモ操作ガイド](docs/demo-guide.md) を参照してください。
主要機能の実装状況と最新の検証結果は [機能確認表](docs/feature-status.md) にまとめています。

案件サンプルは起動時に自動投入しません。初期利用者はデモ12名（営業1名・エンジニア9名・リーダー2名）と管理者1名で、新規登録した利用者もDBに保存します。既存DBがある場合は登録済みの業務データを引き継ぎ、再起動しても削除済みのサンプルは復活しません。従来案件のリーダーは自動では設定しません。

## Excel管理から追加した操作

営業の「案件一覧」は **面談者×案件** で表示し、検索・状態の絞り込み・一次／二次以降の面談履歴を確認できます。依頼作成には元請け・種類（Java、AWS等の自由入力）・営業向け備考・予定面談回数（1〜5回）を追加しました。備考は営業と管理者だけに表示します。

一次通過後は「通過・次回面談を依頼」から同じ案件・面談者へ次の日程を依頼します。各回の日時・URL・所感・質問は保持し、結果をオファー・見送り（先方不合格）・辞退（本人側）に分けて記録できます。初回入場の「確認」は面談者が操作し、その面談者の「入場中」に移動した状態を「参画（入場済み）」として扱います。

管理者でログイン後、「案件管理」から案件遂行者1名・フォロー者複数名を後から氏名で登録できます。フォロー者は1行1名・20名までです。案件名・会社情報・参画者・種類・備考・案件概要も編集できます。同じ案件の担当情報・基本情報は、その案件の各面談者に共通で反映します。遂行者・フォロー者の入力でログイン権限は変わりません。

既存DBは起動時に追加項目を反映し、保存済みデータを引き継ぎます。Excelファイルの自動取り込みは含みません。

営業の「面談依頼を作成」は別タブで開きます。「一時保存」を押すと、入力途中の項目と添付したスキルシートを保存できます。次回は同じ営業アカウントで作成画面の「自分の下書き」を開き、「再開」を選んでください。正式に依頼を登録すると、その下書きは一覧から消えます。

予定表の「今日」と直近の予定はJSTの現在日時に従います。エンジニアの日程回答・所感、リーダーの選定チェックは、同じログイン画面内のタブ／案件移動では保持します（再読み込み・ログアウトを跨ぐ下書き保存ではありません）。営業の対応待ちからは所感・質問の確認と次回面談の依頼へ直接進めます。

## 確認コマンド

アプリを起動した状態で、プロジェクトのフォルダから実行します。

```powershell
npm.cmd run typecheck
npm.cmd run build
npm.cmd run verify:auth
powershell -NoProfile -ExecutionPolicy Bypass -File backend/verify.ps1
node backend/verify-accounts.mjs --with-frontend
# Excel項目・複数回面談・管理画面の担当設定・入場確認（作成したテストデータは終了時に削除）
node backend/verify-excel-workflow.mjs
# 日付境界の単体確認（このコマンドのみNode.js 22.13以降）
node scripts/verify-business-date.mjs
```

バックエンドの構成とAPIは [backend/README.md](backend/README.md)、通し操作の確認記録は [検証記録](docs/verification.md) を参照してください。

## 起動できない場合

- JDK／PostgreSQLが見つからない：上記の `JAVA_HOME`／`DEALHUNTER_POSTGRES_BIN` を、実際のインストール先に設定します。
- 依存関係の取得に失敗する：npmレジストリとMaven Centralへ接続できることを確認して、再実行します。
- ポートが使用中：`3100`（Next.js）・`8080`（Java）・`15432`（専用PostgreSQL）の使用状況を確認します。
- 旧DBポート `55432` はWindowsのTCP予約範囲と重なり、使用中でなくても `Permission denied` で起動できない場合があります。更新後は、専用DBが停止している状態で起動すると、登録済みデータを保持して `15432` へ自動移行します。稼働中の旧DBは、先に `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-backend.ps1` で停止してください。
- API／DBの起動に失敗する：`.local/api-error.log` と `.local/postgres.log` を確認します。Javaだけ再起動する場合は上記の `-Restart` を使います。

`.local` 内のDB・認証情報・ログと、生成された依存ライブラリはGit管理対象から除外しています。共有するのはソースコードで、各環境の保存済み案件や添付ファイルはリポジトリに含まれません。
